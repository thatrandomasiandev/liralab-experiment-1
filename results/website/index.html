Insights

What we take from this sweep

Interpretation first. Charts and tables farther down are the evidence; raw per-update numbers are in the appendix.

Main call

On Walker-walk, the ε = 0.2 collapse looks like a reward-model problem under label noise, not a clean case of SAC overoptimizing a reward that is still mostly right. Held-out and fixed-reference preference accuracy stay low (≈ 0.60 / 0.64) while train-fit stays ≈ 0.98, so the model is matching flipped labels rather than the true ranking. True return falls to ≈ 44 versus ≈ 880–950 at ε ≤ 0.1.

Why not Goodhart as the primary story

Between reward updates the RM is frozen by construction. In those windows, proxy rising while true falls is rare: 0/10 windows at ε ≤ 0.1 and 1/10 at ε = 0.2 under a simple early/late split (late-half proxy mean up by more than 5, true mean down by more than 5). The long post-feedback freeze at ε = 0.2 looks stuck-bad more than proxy racing away from true.

Shape of the noise effect

Failure is not a smooth slope across ε. ε ∈ {0, 0.05, 0.1} all finish with strong return; only ε = 0.2 breaks. Mild Mistake noise is tolerated here; heavy noise is not. Fixed-reference accuracy also drifts down across updates at ε = 0.2 (≈ 0.73 → 0.64), which fits later noisy updates damaging an early region.

What this does and does not settle

Logging train / held-out / on-policy / fixed-ref accuracy plus frozen-window proxy vs true is enough to pull the two mechanisms apart on this run. It does not settle multi-seed stability or other domains. Treat the claim as a first readout: one seed per ε, Walker only, heuristic Goodhart test.

Abstract

How hard is it to discern reward-model accuracy decay from SAC overoptimization on a frozen, slightly wrong reward?

Preference-based RL methods such as PEBBLE often collapse when preference labels are noisy. B-Pref and related benchmarks usually report only downstream return, so those two failure modes stay entangled: the learned reward model’s accuracy gets worse, or Soft Actor-Critic amplifies a small, roughly constant reward error (Goodhart / overoptimization) while the reward is frozen between discrete updates. Separating them is not hard once you log the right signals; it is hard if you only watch return.

We add logging to PEBBLE’s discrete reward-model updates and evaluate on Walker-walk under a Mistake teacher with ε ∈ {0, 0.05, 0.1, 0.2}, 500k environment steps, and one seed per ε. At every reward-model update we record preference accuracy on four sets—train, held-out (20% of each query batch, never used for fitting), on-policy pairs with clean oracle labels, and a fixed reference set frozen after pre-training. Between updates the reward model weights do not change; in those frozen windows we score the same rollouts with proxy return (r̂) and true return (ground truth).

Final true return stays high for ε ≤ 0.1 (≈ 880–950) and collapses at ε = 0.2 (≈ 44). At ε = 0.2, held-out and fixed-reference accuracy end near ≈ 0.60 and ≈ 0.64, versus ≈ 0.87 and ≈ 0.85 under Oracle (ε = 0), while train-fit accuracy remains ≈ 0.98—consistent with fitting flipped labels rather than recovering the true preference ranking. A simple within-window Goodhart check (late-half proxy mean up by more than 5 while true mean down by more than 5) fires in 0 of 10 windows for ε ≤ 0.1 and in 1 of 10 windows for ε = 0.2. On this sweep, collapse lines up with reward-model generalization failure under label noise more than with SAC overoptimizing a still-accurate frozen reward. Limits: one seed per ε, Walker-walk only, and a heuristic Goodhart window test.

Reading the research question

RM accuracy / label noise

Primary story. At ε=0.2, held-out and fixed-ref never approach Oracle levels while train accuracy stays ~0.98—the model fits noisy labels. Collapse lines up with that generalization gap.

Goodhart / overoptimization

Weak support here. Only 1/10 frozen windows at ε=0.2 look Goodhart-like (proxy↑ true↓). The long post-feedback freeze looks more stuck-bad than proxy racing away from true.

Caveats

  • Single seed per ε
  • Walker-walk only
  • On-policy accuracy is high-variance
  • Goodhart test = simple early/late window split
